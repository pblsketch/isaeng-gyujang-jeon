# js/data — 이야기와 글(교사가 고치는 자료)

게임에 보이는 글과 숫자는 모두 이 폴더에 있다. 파일마다 전역 하나를 채우고, 엔진(`js/game/`)이 그 전역을 불릴 때 읽는다. 같은 파일을 점검과 글 확인 도구가 엔진 없이 Node `vm`에서도 실행한다.

## 맡는 것

- **이야기 자료**
  - `walls.js` — 담 앞 순간 다섯(`WALLS[순간]`): `w1-poem`·`w1-parents`(1막), `w2-bandit`(2막), `w3-border`·`w3-propose`(3막). 수단 목록(`means`), 원작에 맞는 수단(`ok`), 제목(`title`), 들어가는 글(`intro`), 수단마다 그 순간의 행동 글(`opts`), 세계의 반응 세 겹(`react[수단].first·again·hint`). `w3-propose`는 답 고르기(`kind:'answer'`, `answers:['stay','entrust']`, 단추 글 `labels`)이고 `together`(이생의 '함께 저승에' 말 `isaeng` + 최 씨의 원작 답 `reply`, 둘 다 원문·풀이)는 고르기 앞에 나오는 대화다.
  - `cards.js` — 낱말 카드(`act1`·`act2`의 `give`·`decoy`·`blanks`, 정답 표 `answer`, 카드 설명 `words`), 맞지 않는 카드에 인물이 하는 말(`replies[빈칸][카드]`, `default`), 결과 화면 '만남과 이별' 표 세 줄(`table`).
  - `okru.js` — 옥루춘 여덟 구(`lines`, 원문+풀이)와 대목 회상(`recall`: `0-1` 고정+`default`, `2-3`·`4-5`는 `byMind.treasure·rites·poems`, `6-7` 고정), 앞뒤 글(`intro`·`after`·`note`).
  - `finale.js` — 반복의 뜻 물음(`repeat`), 근거 장면 넷(`scenes`: `reunion`·`rites`·`okru`·`farewell`), 전기적 요소 한 줄(`jeongi`, `ref`가 2막 혼 단계를 가리킴), 「만복사저포기」(`mbs`: 줄거리 카드·두 고르기 `picks`(`q1`·`q2`, 보기 셋씩)·원작 사실·맺음), 만복사 한 줄(`mbsSame`), 되짚기 질문 둘(`review`), 「김현감호」 한 줄(`kimhyeon`), 원전으로 나가는 문 안내(`sourceDoor`), 결과·마무리 화면 이름표(`ui`).
  - `places/*.js` — 거점 여섯(`PLACES[id]`): `prologue`(들어가기), `act1`(정원), `act2`(피란길), `act2night`(밤의 최 씨 집), `act3`(세 구역), `epilogue`(맺음). 맵 격자·자리·사람(`cast`)·목표(`beats`)·단계(`steps`)·장면 설명(`scenes`), 바로가기 30초 요약 카드(`summary`, 1·2·3막 거점).
- **엔진이 읽는 자료**: `flow.js`(제목, 첫 1분의 미션, 거점 차례 `order`, 막 이름·미션 `acts`, 거점 이름 `places`, 바로가기 글 `shortcut`), `texts.js`(표시 이름·색, 전체 화면·세로 안내·처음부터 확인, 얻은 것 알림 틀, 잠긴 할 일 안내 `LOCKED`, 접은 원문 단추 `FOLD`, 키 안내, 담·빈칸 화면 이름표 `WALL`·`BLANK`. `HON`(혼 화면 이름표)·`MEANS`(수단 이름)를 두면 엔진의 대체 글보다 먼저 쓰이지만 지금은 없다), `notes.js`(표시 다섯의 설명, 만든 사람·원문 출처 줄 `credits`, 결과 화면 틀 글 `result`), `people.js`(인물 id·이름·색·도트·초상 자리), `sprites.js`(임시 도트·소품 도형), `bgm.js`(곡 목록 `tracks`와 게임 안 출처 줄), `credits.js`(출처 화면의 소재 출처).

## 맡지 않는 것

- 규칙의 동작(담 높이 셈, 반응 세 겹 고르기, 혼 열림, 장사 잠김, 확정 기록, 바로가기)은 `js/game/`에 있다. 여기서는 글과 자리, 열림 조건의 자료만 바꾼다.
- 화면 모양과 엔진 대체 글은 `js/game/`·`css/`의 일이다.
- 출처 목록 표(`credits/*.tsv`)와 자산 파일(`assets/`)은 이 폴더 밖이다. 곡을 바꾸면 `bgm.js`와 `credits/bgm.tsv`를 함께 맞춘다.

## 지켜야 할 것

- **원문**(`han`): `sources/wikisource-geumosinhwa-raw.txt`(위키문헌 「번역:금오신화」)의 글자만. 기억으로 쓰거나 지어 넣지 않는다. 한 덩이(한 화면)에 1~2구. 늘 `ko`(새로 옮긴 풀이)와 짝. 사본의 오자로 보이는 글자(예: 黃壞, 匙筋)가 든 대목은 고르지 않는다.
- **번역문 금지**: 풀이·장면 글·인물 말·반응·요약·만복사 줄거리는 모두 새로 쓴다. 교과서·지도서·번역서 문장을 옮기지 않는다(교과서와는 뜻이 어긋나지 않는지만 대조한다). 교과서 출판사 이름은 어디에도 쓰지 않는다.
- **표시와 상태**: 모든 글 덩이에 `mark`(`원문`·`풀이`·`게임 설정`·`이본 노트`·`해석`), `src`(출처, 근거 대목), `status`(지금은 모두 `확인 전` — 글 자료 점검이 요구한다). 게임이 지어낸 것(수단, 담, 낱말 카드, 마음 둔 곳, 혼으로 걷는 길, 할 일 순서 자유, 반응 대사, 막 미션)은 `게임 설정`. 사람의 `cast[…].talk`은 표시를 적지 않으면 `게임 설정`으로 본다.
- **글 길이**: 사건 화면 글 180자, 반응 글(`react`·`replies`) 70자, 원문 한 화면 1~2구.
- **반응 글은 인물·세계의 말**: '틀렸다' 투, 학생 탓을 쓰지 않는다. 실마리(`hint`)는 다음에 해 볼 쪽을 인물의 말로 넌지시. `w3-propose`의 `stay` 반응에도 `again`·`hint`가 있어야 한다(다시 고를 수 있으므로).
- **넘지 않는 선의 말**: 점수·등급·순위·랭킹·시간 제한·제한 시간·남은 시간·시간 초과·게임 오버·정답·오답·틀렸·'틀린 '·감점·득점·만점·실패·맞았습니다·맞혔·채점 결과·score·rank를 쓰지 않는다. 그 글자가 든 낱말(`정답게`)도 걸린다. '정답이 없는'처럼 부정하는 꼴만 된다.
- **민감한 장면**: 도적의 위협은 `w2-bandit`의 `intro` 한 줄, 꾸짖음(`a2-rebuke`) 바로 뒤 암전(`a2-dark`, 그림 자리 없음, 폭력은 한 줄 서술), '살을 발라냄'은 암전의 원문 카드(`quote`, 펼침 `fold:true`) 풀이에만, 해석 카드(`a2-era`) 한 장. 1막 밀회는 "밤마다 몰래 만났다" 한 줄. 화면의 시는 최 씨가 읊은 시와 여덟 글자, 옥루춘뿐(이생의 시들은 싣지 않는다). 이생의 죽음은 `e-death` 암전 한 줄. '함께 가자'는 고르기에 없다 — `together`에 `options`·`choose`·`pick`을 두거나 `answers`·`labels`·`react`에 `together`를 넣으면 점검이 실패한다.
- **id는 바꾸지 않는다**(거점·목표·단계·순간·빈칸·할 일·마음 둔 곳·근거 장면). 저장 기록의 장부 열쇠(`b:거점:목표`, `s:거점:단계`)와 점검이 id로 묶여 있다. 새 것은 새 id로.
- 장면 id는 `sc_<거점>_<무엇>`. `scenes`에 `caption`(그림 설명)과 `prompt_hint`(영어, 그림 안에 글자 없음)를 적는다. 폭력·죽음 장면에는 그림 자리를 두지 않는다.
- **엔진 없이도 실행되어야 한다**: 거점 파일은 `G.world.mk`가 없으면 같은 방식의 작은 대체 함수로 격자를 만든다(대체 함수는 `rect`만 안다 — 다른 op를 쓰면 엔진 없이 읽은 격자가 달라진다). 지금 기록을 읽는 값(3막 `year`, `b-tasks`의 `map`·`spawn`)은 getter로 두고, 엔진이 없거나 오류가 나면 처음 값을 돌려준다.
- **한 전역 배열에 두 파일이 더하지 않는다**: 글 확인 도구는 엔진 자료 파일을 하나씩 따로 실행하므로, 두 파일이 같은 배열에 `push`하면 둘 다 `[0]` 자리가 되어 문서 자리가 겹친다. 다른 파일이 더하는 칸은 이름 있는 칸으로(글꼴 출처 `CREDITS.fonts`, 배경음 출처 `CREDITS.sections`의 `id:'bgm'`).
- 글자는 부분 글꼴에 들어 있어야 보인다. 원본 글꼴에 없는 기호(✎ ▸ ✕ 등)를 쓰지 않는다.

## 이 폴더의 방식

- 파일마다 전역 하나를 채우고(`window.WALLS`, `window.PLACES.act1` …), 파일 안 도우미는 즉시 실행 함수 안에 둔다(파일끼리 이름이 부딪지 않게).
- **글 덩이**: `{ t, mark, src, status }` (+ 말하는 인물 `who`). **원문 덩이**: `{ han, ko, mark:'원문', src, status }` (+ `who`). 파일 머리의 도우미 `p(…)`(풀이)·`g(…)`(게임 설정)·`w(…)`(원문)·`i(…)`(해석)와 상수 `ST = '확인 전'`으로 만든다.
- **대사 줄**(`lines`·`intro`): 글 덩이 또는 원문 덩이. 원문 덩이는 원문+풀이 한 장으로 보인다. 글자 그대로의 문자열 줄은 그 단계의 `mark`·`src`·`status`를 따른다.
- **카드**: `{ type:'card', card:{ title, body, mark, src, status, quote:{ han, ko, … } } }`. `body`의 `\n`은 문단 나눔. 카드 앞에 `lines`를 둘 수 있다.
- **단계 종류**: `say`, `card`, `wall`(`id`가 곧 순간 열쇠), `blank`(`act`), `hon`, `tasks`(`list`), `mind`(`q`·`note`·`options[{id,t}]`), `okru`, `propose`(`wall:'w3-propose'`), `blackout`(`t` 한 줄, 원문 카드는 `quote`+`fold`), `summary`(거점의 `summary`를 씀).
- **혼 단계**(`act2night`의 `n-hon`): `walk`(걷기 안내), `reveal`(`name:'혼'`, `tag:'전기적 요소'`, `explain`), `reason`(원문 天帝…假以幻體 두 덩이), `note`(원작에서는 3막 끝 저녁의 말임), `setting`(혼으로 걷는 길은 게임 설정).
- **낱말 카드**는 단계의 `fx: { word: '담장' }`으로 저절로 준다(빈칸 단계보다 앞). 1막: 담장·울주·혼인·과거 급제, 2막: 홍건적의 난·피란·꿈·환신.
- **표 문장**의 `{빈칸 열쇠:조사}`: 그 자리에 고른 낱말을 넣고, 조사는 받침 있는 꼴(을·이·으로)로 적는다. 낱말에 받침이 없으면 를·가·로로 바꿔 붙인다.
- **3막**(`act3`): `tasks.<할 일>`에 `name`·`goal`·`map`·`spot`·`time`(때 딱지)·`steps`, 장사는 `need:['treasure','bones']`·`locked`·`after:'장사 뒤'`. `border`는 경계 구역(`wall:'w3-border'`, `map`, `spot`, `spawn`(짧은 길로 옮길 자리), `back`, `goal`, `nudge`, `path`, `leave`). `times`는 때 딱지 셋. 노복은 `cast.home.servant.after:'burial'`(장사 뒤에만). 할 일 사이 왕복은 두 번 이내로 배치한다.
- 인물 id: `choi`(최 씨, 학생), `isaeng`, `hyanga`(향아), `choi_father`, `choi_mother`, `isaeng_father`(말로만, 맵에 세우지 않음), `maepa`(매파), `servant`(노복), `bandit`(도적). 이름·색은 `people.js`.
- 곡을 장면에 고르는 것은 자료의 `music:'장면 id'`(거점·목표·단계). 곡 이름은 `BGM.tracks`의 열쇠여야 한다.

## 고친 뒤

1. `node tests/run-all.mjs data limits` — 담 앞 순간이 정한 표(1막 2, 2막 1, 3막 2, 원작에 맞는 수단)와 같음, 반응 세 겹, 빈칸과 카드의 때, 옥루춘 회상 짝, 표시·출처·상태, 원문 한자가 원문 사본에 그대로 있음, 글 길이, 넘지 않는 선의 말.
2. `node tools/review-doc.mjs` — 글 확인 문서를 다시 만든다(엔진 자료의 글을 바꿔도). 다시 만들지 않으면 글 확인 문서 점검이 실패한다.
3. 화면 글자(한자·기호)가 새로 생겼으면 `python tools/build_fonts.py`.
4. `node tests/run-all.mjs` 전체 종료 0. 맵·자리·목표를 바꿨으면 그 막의 크롬 점검(`act1`·`act2`·`act3`·`flow`)이 특히 중요하다.
- 교사가 확인한 글을 `확인됨`으로 바꾸면 글 자료 점검(`tests/check-data.mjs`의 상태 검사)도 함께 바꿔야 통과한다.
