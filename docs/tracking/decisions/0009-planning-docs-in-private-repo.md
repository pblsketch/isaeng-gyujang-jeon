# 0009 비공개인 동안 기획 문서를 저장소에 함께 올린다

- 날짜: 2026-10-09 · 상태: 정함

## 맥락

기획 자료(`design/` — 교과서 쪽수가 적힌 글 목록, 외부 검토와 채점 기준표, 원문 사본, 그림 시안)는 만드는 동안 계속 쓰이고 여러 작업이 함께 본다. 이 게임은 언젠가 공개(GitHub Pages)와 교과서 납품을 염두에 두지만, 이 자료에는 교과서 쪽수와 검토 기록처럼 공개하기 어려운 것이 들어 있다.

## 결정

저장소 `pblsketch/isaeng-gyujang-jeon`을 비공개로 두는 동안에는 `design/`을 함께 커밋한다. 공개로 바꾸기 전에 `design/`을 git 기록에서까지 지운다. 교과서 PDF·추출본과 출판사 이름은 비공개 동안에도 넣지 않는다. 그림·글꼴·소리의 생성 원본은 `.gitignore`로 처음부터 뺀다.

## 다른 안

- **기획 문서를 이 컴퓨터에만 두기**: 공개 전환이 간단하지만, 원문 사본을 쓰는 글 자료 점검을 다른 환경(새로 받은 사본)에서 돌릴 수 없고 기획 기록이 한 기기에만 남는다.
- **기획 문서용 저장소를 따로 두기**: 게임 저장소는 깨끗하지만 원문 사본을 두 저장소에 맞춰 두어야 한다.

## 결과

- 공개 전환은 이력 다시 쓰기(강제 push 포함) 없이는 할 수 없다. 그 전에 저장소를 공개로 바꾸면 기획 문서가 이력째 드러난다.
- 이력을 다시 쓰면 글 자료 점검이 기대는 원문 사본(`design/sources/`)도 저장소에서 빠지므로, 그때 원문 대조를 어디서 할지 함께 정해야 한다.
- 권리 점검은 `design/`을 '추출본·생성 원본 미추적' 검사에서만 빼고, 출판사 이름 검사는 `design/`까지 포함해 훑는다.

## 그 뒤(2026-10-10)

공개 전환을 정하면서 원문 사본을 `sources/`로 옮기고, `design/`을 모든 커밋에서 지운 뒤(이력 다시 쓰기, 강제 push) 저장소를 공개로 바꾸고 GitHub Pages를 켰다. `design/`은 `.gitignore`에 더해 만드는 컴퓨터에만 남는다. 이력을 다시 쓰기 전의 저장소 전체는 저장소 밖에 묶음 파일(git bundle)로 백업해 두었다.
