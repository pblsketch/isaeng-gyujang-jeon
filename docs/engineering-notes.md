# 알아 두어야 할 것

## `tests/node_modules` 연결과 작업 사본

- **증상**: git 작업 사본(worktree)을 만들어 점검을 돌린 뒤 `git worktree remove`로 지웠더니 형제 게임 「최척전」의 `../choecheok-jeon/tests/node_modules`(Playwright 설치본)가 통째로 비었다. 그 뒤 두 게임 모두 크롬 점검이 `playwright` 패키지를 찾지 못해 시작부터 멈춘다.
- **까닭**: 이 저장소의 `tests/node_modules`는 형제 폴더 설치본으로 가는 Windows 디렉터리 연결(junction)이다. 작업 사본 안에 같은 연결을 만들면, `git worktree remove`가 작업 사본의 무시된 파일을 지우면서 연결을 따라 들어가 **연결 대상의 파일을 지운다**.
- **대처**: 작업 사본 안에 `node_modules` 연결을 만들지 않는다. 작업 사본들을 담는 **상위 폴더**에 `node_modules` 연결을 하나 두면, Node가 `tests/`에서 위로 거슬러 올라가며 `node_modules`를 찾으므로 작업 사본 안의 점검도 Playwright를 찾는다. 작업 사본을 지운 뒤에는 `ls ../choecheok-jeon/tests/node_modules/playwright`로 형제 설치본이 그대로인지 확인한다. 비었으면 다시 설치해야 하는데, 설치는 사용자 승인이 필요하다.

## 글을 고친 뒤 점검이 실패할 때

- **글 확인 문서 점검 실패**: `js/data/`의 글(엔진 자료 `flow`·`texts`·`notes`·`people`·`credits`·`bgm` 포함)을 한 글자라도 바꾸면 커밋된 글 확인 문서와 도구가 새로 만든 결과가 달라져 실패한다. `node tools/review-doc.mjs`로 다시 만들고 함께 커밋한다. 확인만 하려면 `node tools/review-doc.mjs --check`(다르면 종료 1).
- **글 확인 문서의 자리 겹침**: 글 확인 도구와 점검은 엔진 자료 파일을 **파일마다 따로** Node `vm` 맥락에서 실행한다. 그래서 `credits.js`와 `bgm.js`가 둘 다 `CREDITS.sections`에 하나씩 `push`하면, 각자의 맥락에서 둘 다 `CREDITS.sections[0]`이 되어 문서의 '자리'가 겹치고 점검이 '같은 자리가 두 번 실림'으로 실패한다. 다른 파일이 더하는 칸은 이름 있는 칸으로 둔다(글꼴 출처가 `CREDITS.fonts`인 까닭).
- **넘지 않는 선 점검 실패**: 화면 문자열에 '실패'·'정답'·'점수' 같은 말이 들어가면 걸린다. '저장 실패' 같은 엔진 안내 글, '정답게' 같은 낱말도 걸린다. 주석은 보지 않으므로 주석의 말은 괜찮다.
- **글 자료 점검 실패(상태)**: 지금 글 자료 점검은 모든 글의 상태가 `확인 전`이기를 요구한다. 교사가 확인한 글을 `확인됨`으로 바꾸면 그 점검(`tests/check-data.mjs`의 `STATUS`)도 함께 바꿔야 통과한다.

## 글꼴에 없는 글자

- **증상**: 화면 코드나 자료에 기호 하나(예: ✎ U+270E, ▸ U+25B8, ✕ U+2715)를 넣으면, `python tools/build_fonts.py`로 글꼴을 다시 만들어도 글꼴 점검이 '빠진 글자'로 실패한다.
- **까닭**: 부분 글꼴은 고운바탕 → (없으면) Noto Serif KR → (그래도 없고 U+3400 이상인 한자만) Noto Serif SC 차례로 채운다. 위 기호는 세 원본 글꼴 어디에도 없다. 글꼴 점검과 글꼴 도구는 `js/**`·`css/**`·`index.html`의 **모든 글자를 주석까지** 센다.
- **대처**: 원본 글꼴에 있는 기호로 바꾼다 — 줄표 `—`, 꺾쇠 `›`, `▶`·`▼`·`▲`·`◆`, `·`, `…`. 닫기 아이콘은 글자 대신 SVG로 그린다(`G.app.ICON.close`). 주석에도 이런 기호를 쓰지 않는다. 새 글자를 넣은 뒤 `node tests/run-all.mjs fonts`로 확인한다.
- 드문 원문 한자(挈·頥 등)는 Noto Serif KR에 없어 Noto Serif SC 부분 글꼴(`hanja-extra*.woff2`)이 채운다. 원문을 바꿔 새 한자가 들어오면 글꼴을 다시 만든다.

## 확정 기록과 되돌리기 장부

- **증상(막아 둔 것)**: 단계 도중에 새로고침하면 같은 수단 시도가 기록에 두 번 들어가거나, 반대로 이미 본 시도가 사라진다.
- **까닭**: 엔진은 단계를 시작할 때 `G.save.snapKeys`(`flags`·`applied`)를 떠 두었다가, 그 단계 도중 다시 열면 그 값으로 되돌리고 단계를 다시 펼친다. 한 번만 반영 장부 `applied`도 되돌려지므로, 시도를 장부로 막으면 '장부는 지워지고 시도는 남아' 다시 펼친 단계에서 같은 시도가 또 들어간다.
- **대처**: 반응을 본 시도는 확정 칸(`G.save.COMMITTED`)에 곧바로 적고, 시도 번호 `n`(단추를 그릴 때 `G.rules.nextAttempt`로 받은 값)으로 같은 시도를 막는다. 담 앞 단계의 효과(`stepRules.wall`·`propose`)는 기록을 읽기만 하므로 되돌린 뒤 다시 적용해도 기록이 늘지 않는다. 새 확정 칸을 만들면 `COMMITTED`에 넣고 `snapKeys`에는 넣지 않는다. 확인: `node tests/run-all.mjs rules`(확정 기록이 되돌리기에 지워지지 않고 두 번 들어가지 않음)와 `flow`(수단 반응 직후·빈칸 첫 시도 직후·3막 할 일 일부 뒤에 다시 열기).

## 혼이 열리는 때는 지도 위 자리로 판정한다

- 혼 단계는 사건 화면을 잠시 걷고 학생을 걷게 한 뒤, 80ms마다 `G.world.test.state()`의 학생 자리를 읽어 **처음 자리에서 10px 이상** 움직이면 그때 혼을 연다. 맵이 바뀌었거나 자리를 못 읽으면 기다린다.
- `G.world.test`는 이름과 달리 점검 전용이 아니다. 이것을 지우거나 `state()`의 `x`·`y`·`map`을 바꾸면 혼이 열리지 않는다(맵이 없는 시험 자리에서만 '걸어 본다' 단추로 대신한다).
- 점검 손잡이 `G.world.test.teleport`로 옮겨도 자리가 바뀌므로 혼이 열린다. 걷기 입력 자체를 확인하려면 방향키·조이스틱으로 걸어야 한다.

## 3막 '짧은 길'은 순간 이동이다

- 할 일 넷을 마쳤는데 경계를 아직 겪지 않았으면 효과 `taskPath`가 `G.tasks.openPath()`를 불러 학생을 경계가 있는 들(`valley`)의 `border.spawn`(경계 몇 걸음 앞)으로 **옮기고** "짧은 길이 보인다" 글을 보인다. 지도에 새 통로가 생기는 것이 아니다.
- 지도의 입구(`doors`)는 맵을 불러올 때(`loadMap`) 맵 정의에서 한 번 만들어진다. 게임 도중 맵 정의에 입구를 더해도 그 맵을 다시 불러오기 전에는 생기지 않는다. 새 통로가 필요하면 맵 정의에 처음부터 두고 `when` 조건으로 막는 쪽을 쓴다.
- 3막 할 일 사이 왕복은 많아야 두 번이 되게 배치되어 있고 3막 점검이 센다. 할 일 자리나 입구를 옮기면 `node tests/run-all.mjs act3`로 확인한다.

## 때 딱지는 저장하지 않는다

3막 때 딱지(재회 이튿날 → 장사 뒤 → 서너 해 뒤)는 `G.tasks.timeOf(st)`가 `st.tasks.burial`과 `st.mind`에서 구한다. 거점·맵의 `year`는 이 값을 읽는 getter이고, 엔진 없이 읽히면 '재회 이튿날'을 돌려준다. 그래서 딱지를 직접 바꾸는 코드는 소용이 없고, 장사가 기록되기 전에 '장사 뒤'를 보이려면 장사 단계(`t-burial`)의 효과로 먼저 확정해야 한다(지금 그렇게 되어 있다). 장사 기록과 마음 둔 곳은 되돌아가지 않으므로 딱지도 앞으로만 간다(바로가기로 3막부터 새로 할 때만 처음으로).

## 크롬 점검의 소음과 틈

- **`ERR_ABORTED` 배경음**: 거점에 들어서면 곧바로 그 거점의 곡으로 바꾸므로, 아직 받던 타이틀 곡(`assets/bgm/*.mp3`) 요청을 크롬이 끊고 `net::ERR_ABORTED`를 남긴다. 게임 오류가 아니다. 점검 도우미(`tests/lib.mjs` `open`)는 **배경음 mp3의 끊김만** 빼고 센다 — 없는 파일(404)이나 다른 파일의 끊김은 그대로 오류다. 이 거르기를 넓히지 않는다.
- **대화창을 닫은 직후 300ms**: 엔진은 대화창을 닫은 뒤 300ms(`G.world.closedAt`) 동안 E·Enter·Space·Z를 말 걸기로 받지 않는다(닫는 키가 곧바로 다시 말을 거는 것을 막음). 점검에서 대화를 끝낸 뒤 곧바로 E를 누르면 먹지 않는다 — `talkTo`가 380ms를 기다리는 까닭이다.
- **`scrollIntoView` 금지**: 글 칸 안 요소에 `scrollIntoView`를 쓰면 놀이 화면 틀까지 굴러 HUD가 잘린다. `G.ui.reveal(el)`은 그 요소를 담은 글 칸만 굴린다.
- 엔진의 목표 꼴(beats·순서 없는 할 일·되풀이 구역)을 바꾸면 엔진 틀 점검의 시험 자료(`tests/fixtures/smoke-places.js`, 실제 `PLACES`와 `FLOW.order`를 바꿔 끼움)와 담 화면 시험 자료(`tests/fixtures/walls-places.js`)도 함께 바꾼다.

## 권리 점검은 이력 전체를 본다

권리 점검은 지금 파일뿐 아니라 `git log --all -p`의 모든 변경 내용과 커밋 글, 그리고 아직 추가하지 않았지만 무시되지 않은 새 파일까지 훑는다. 그래서 출판사 이름이 한 번이라도 커밋되면 뒤 커밋에서 지워도 점검은 계속 실패하고, 이력을 다시 써야만 풀린다(사용자 승인 필요). 저장소 폴더 안에 메모 파일을 만들 때도 같다 — `.gitignore`에 없는 새 파일은 커밋 전에도 걸린다.

## 그림 시안 도구(Codex)

- 프롬프트는 영어(ASCII)로만 쓴다. `tools/gen.ps1`이 프롬프트를 명령문 안에 그대로 넣어 넘기므로 한글이 섞이면 깨진다(도구가 `WARN … non-ASCII`를 찍는다).
- Codex에게 프롬프트 파일을 읽게 하면 샌드박스가 파일 읽기를 막아 그림이 나오지 않는다. 그래서 도구가 파일 내용을 명령문에 넣는다.
- 전역 `~/.codex` 설정(플러그인·MCP)으로 띄우면 시작이 몇 분씩 멈춘다. 도구는 최소 설정만 둔 임시 `CODEX_HOME`을 만들어 쓴다. 전역 모델을 Codex가 받지 않으면 `-UseModel gpt-5.6-sol`로 고른다.
- 요청한 크기와 돌아온 크기가 다를 수 있다(장면 1536×1024 요청 → 1672×941이 오기도 함). 비교 그림은 칸에 맞게 자른다.
- 시안의 옷차림은 고려 말 옷을 요청해도 조선 한복·갓처럼 나왔다. 본 그림을 만들 때 고려 말 옷차림을 프롬프트에 더 강하게 적고 결과를 눈으로 확인한다.

## 그 밖의 숨은 동작

- **배경음 크기**: 곡은 모두 -17 LUFS인데 `act3.mp3`만 -22 LUFS로 만들어져 `BGM.tracks.act3.gain`이 1.75다. 곡을 바꾸면 gain도 다시 맞춘다.
- **저장 열쇠가 생기는 때**: 타이틀에서 설정만 바꾸면 `isaeng-gyujang:settings`만 생기고 진행 열쇠는 만들지 않는다(진행도 이름도 없으면 지운다). 그래서 설정만 바꾼 뒤 다시 열어도 '이어 하기'가 뜨지 않는다.
- **이어 하기 계산이 두 벌이다**: 실제 이어 하기 자리는 엔진(`G.world.play`)이 장부를 보고 정하고, `G.rules.resumePoint`는 같은 셈을 브라우저 없이 도는 순수 함수로 옮긴 것이다(규칙 점검과 3막 점검이 이것으로 기대 자리를 구한다). 엔진은 목표의 `when` 조건을 보고 건너뛰지만 `resumePoint`는 `when`을 보지 않는다. `when`으로 건너뛰는 목표를 더하면 둘이 갈라질 수 있으니, 엔진 셈을 바꿀 때는 `resumePoint`도 함께 바꾸고 `node tests/run-all.mjs flow act3`로 다시 열기를 확인한다.
- **원문 대조의 범위**: 글 자료 점검은 원문 덩이(`han`)의 한자만 남겨 원문 사본에 그대로 있는지 본다. 구두점·따옴표는 빼고 보므로 구두점 차이는 잡지 않는다.
